# ADR-0025: `memory.correct` —— 更正 = 新 Evidence + 新版本 + SUPERSEDE(USER_CORRECTION)，永不原地改历史证据（研究问题 Q4）

日期：2026-09-05 · 状态：Accepted · 影响面：`crates/application/src/correct.rs`（新，纯 `correction_requested_class`/`authorize_correction`）/ `crates/adapters/src/memory_governance_repo.rs`（新 `correct_atomically`；`append_lifecycle_event` 加 `correction_evidence` 参数）/ `crates/adapters/src/{remember.rs,distill_repo.rs}`（复用其唯一 issuer / version-insert）/ `crates/domain/src/{confirm.rs,context.rs,context_repo.rs,lifecycle.rs}` / `crates/protocol/src/mcp_catalog.rs`（输出联合体计数测试 8→9） / `bins/gateway/src/{mcp_application.rs,memory.rs}` / `contracts/mcp/{memory.schema.json,memory.output.schema.json}` / `bins/gateway/tests/mcp_gateway.rs`。**无新迁移**（复用卡 3 的 `ops.memory_lifecycle_events.correction_evidence_id` 列与 `ops.append_memory_lifecycle` 的 `p_correction_evidence_id` 形参，两者卡 3 已建但未有生产者）。**无新 `ErrorCode`**（§52.1 冻结 18）。前置：卡 1（confirm 门 / `DestructiveOp`）、卡 3（生命周期日志 + `append_memory_lifecycle` + `lifecycle_head_event_id` + `restore`）已在树上。

## 背景
更正是 agent 记忆系统里最高价值的治理动作（用户自己的工作流规则把「用户更正」列为最值钱的 claim 类型），而它此前**完全缺席**：`crates/application/src/correct.rs` 只是一行占位注释、零 `pub` 项，全仓无 `CorrectionEvent` 类型。spec :8568 定死了硬规则——**用户编辑写一条 Correction Event 加一个新版本，永不原地改历史证据**——却没有为它定义任何形状（表或类型）。这是研究问题 Q4 要解决的空白。

## 研究问题 Q4（更正需要新表吗）
**决定：不需要新表。一次更正 = 一个事务里 {INSERT Evidence E2（origin DirectUserInput）; INSERT Memory M2（authority 经 AuthorityPolicy，非继承）; memory_evidence M2<-E2 PRIMARY; UPDATE M1 status=superseded, superseded_by=M2 WHERE status='active'; append `SUPERSEDE`（reason USER_CORRECTION, correction_evidence_id=E2）}。**

- 一条更正**就是**一次 supersede，只是它额外携带「用户直接输入的新证据」。卡 3 的 `ops.memory_lifecycle_events` 已经是 supersede 的统一日志，且已带 `correction_evidence_id` 列（卡 3 前瞻加、无生产者）——本卡是它的第一个生产者。因此更正复用 supersede 链（`superseded_by`）+ 生命周期日志，不新开表、不新开第二条 lifecycle 写路径（阶梯第 2 级：复用已在几文件之外的东西）。
- `domain::lifecycle::CorrectionEvent`（新，纯值对象）把「一条更正的形状」定死成 `(op=SUPERSEDE, reason=USER_CORRECTION, 有 replacement, 有 correction_evidence)`，让 gateway 结果与审计读者共用同一个「什么算更正」的定义，而不是各自重新推导四元组。这是 Q4 要求的「type/shape」交付物。

## 决定
1. **`DestructiveOp::MemoryCorrect`（D-A，复用卡 1 的门）**：`memory.correct` 走同一个 confirm 门（`run_confirmed_write`），线上**无 successor 参数**——M2 是在被确认的事务内部铸造的，故 token 的 `successor_id=None`。门机制对 op 泛型，零改动接纳新 key。`DestructiveOp::ALL` 长度 6→7。
2. **`correct_atomically`（一个事务）**：幂等预检（命中同 key+fingerprint 的 SUPERSEDE/USER_CORRECTION 事件 ⇒ 直接返回原 `CorrectDone`，绝不二次铸造 E2/M2——与卡 3 restore 同形，因为更正创建行、重放必须返回原件而非二次创建）→ reserve BMO（只在成功路径）→ consume token（坏 token = `Conflict`）→ 读 M1 的可见性/reasoning_domain/type（不可见 = `NOT_FOUND`，绝不泄漏）→ 经 `remember::create_evidence_object`+`insert_event_subtype`（**复用其唯一 issuer，绝不手写第二条 evidence INSERT**）写 E2（origin DirectUserInput，可见性从 M1 的证据逐字复制，event_kind=USER_CORRECTION，payload=更正内容）→ 发一张 `MEMORY_LIFECYCLE` 票绑到 E2（**不是 `EVIDENCE_ACCEPTED`**，故 distill worker 不会捡起 E2 再蒸馏——D-C：M2 在此直接物化，无 distill 往返）→ 经 `memory_repo::insert_memory_in_txn`（复用 distill 的 version-insert）物化 M2（memory_records active + memory_evidence M2<-E2 PRIMARY IMMUTABLE；authority 经 `OriginBoundAuthorityPolicy` 对 DirectUserInput 求，**非从 M1 继承**）→ append `SUPERSEDE`（reason USER_CORRECTION，replacement=M2，correction_evidence=E2，24h `undo_deadline`）→ 仲裁 `UPDATE ... WHERE status='active'`（0 行 = `Conflict`，把 E2/M2 一起回滚，与 supersede 同形）→ 结算。**M1 的 `events` 行从头到尾不被触碰**。
3. **Authority 非继承（§10.1/Q4）**：M2 的 `AuthorityClass = OriginBoundAuthorityPolicy.authorize(requested=DirectUserInput.authority_ceiling(memory_type), memory_type, [DirectUserInput], scope)`——一个用户直接更正正当地拿到该 origin 的天花板（多数类型是 `UserCorrection`，`Constraint` 型经 §10.1 row-1 例外升到 `ProjectConstraint`），而不是从 M1 继承一个可能高于更正证据所能证成的类。`memory_type` 从 M1 继承（更正一条 FACT 得一条 FACT）。
4. **可撤销（Q2 一致）**：更正写的那条 `SUPERSEDE`（reason USER_CORRECTION）带 `undo_deadline`，因此**更正本身经 `memory.restore` 可撤**（卡 3 的 `restore_allowed` 对 SUPERSEDE head 返回 Ok）——「更正的撤销 = 卡 3 对那条 SUPERSEDE 的 restore」，不新开撤销路径。
5. **结果形状（D-B）**：`{memory_id: M2, superseded: M1, evidence_id: E2, superseded_at, stream_seq, commit_seq, consistency_token}`（`memory.output.schema.json` 新 `Corrected` 分支）；重放靠 key+fingerprint 幂等。confirmation_required 首呼呈 `{confirmation_required, confirm_token, operation:"memory.correct", target:{memory_id}, expires_at}`（无 successor）。
6. **投影（D-C）**：E2 的 `MEMORY_LIFECYCLE` 票使 M2 像任何 memory 一样经 `memory_evidence(E2) → memory_records(M2)` 被投影解析——不走 remember→distill 往返；验收测试断言更正后 DB 态 + `memory.get`/`enumerate` 见 M2 不见 M1。

## 越界改动（需主线裁决，与 ADR-0018/0019/0020/0024 同一情形）
卡片的「允许改动文件」清单未列全其决定所必然触及的文件；下列改动各由本卡某条决定直接要求，逐条记录：
- `crates/domain/src/confirm.rs`：加 `DestructiveOp::MemoryCorrect`（confirm 门唯一以 `DestructiveOp::parse_operation_key` 认 op，`memory.correct` 必须能解析成一个变体，否则门直接拒——D-A；confirm.rs 文档本就写「每个被门控的 op 加一个变体」）。
- `crates/domain/src/context.rs` 与 `crates/adapters/src/context_repo.rs`：`from_consumed_confirmation` / `apply_binding_write` 的 match 因穷尽性各加一臂（correct 不是 pin/unpin ⇒ 分别 `MissingConfirmation` / `InvalidInput`）。
- `crates/adapters/src/remember.rs`：把 `create_evidence_object`/`insert_event_subtype` 由私有改 `pub(crate)`，供 `correct_atomically` 复用（D-A 明令「复用唯一 issuer，绝不手写第二条 evidence INSERT」；卡片允许清单只含 `distill_repo` 的 version-insert，未含 remember 的 evidence issuer）。
- `contracts/mcp/memory.output.schema.json`：`ConfirmationRequired.operation` 枚举加 `memory.correct`（否则首呼输出校验红），并加 `Corrected` 执行结果分支（D-B）。卡片允许清单只含 `memory.schema.json`（其 `memory.correct` 输入分支此前已预置）。
- `crates/protocol/src/mcp_catalog.rs`：上一条给输出 schema 加了 `Corrected` 分支，广告出的 `stable output union` 因此 8→9 个 `oneOf`；该 crate 的测试逐字断言联合体长度与每个分支的 `$ref`，故同步改 8→9 并加 `oneOf[8] == Corrected` 断言（否则该测试红）。纯测试同步、无行为变更；卡片允许清单未含 `crates/protocol`。
- `SUPPORTED_OPERATION_KEYS` 保持 12 未动（其源文本被 `continuity_get.rs:877` 逐字断言、该测试不在允许清单内）：路由靠 dispatch 的 `key == operation_key()` 臂，不靠该常量，故 `memory.correct` 仍可路由——与既存的 `memory.confirm`（在 schema、不在该常量）同形。

## 验收
`bins/gateway/tests/mcp_gateway.rs::native_mcp_memory_correct_writes_new_version_and_never_edits_evidence`（真 role_gateway LOGIN + 真 PG）：更正（确认）⇒ M1 superseded_by=M2 且 G59-4 恒真；M2 active、memory_type 继承（NOTE）、authority_class=`UserCorrection`（非 M1 的 ProjectConstraint，证「非继承」）；M2<-E2 PRIMARY，E2 origin=DirectUserInput、event_kind=USER_CORRECTION、payload=新文本；**原 Evidence（E1）的 payload_sha256/events.payload 在更正前后逐字相等**（注错：若把 adapter 改成原地 UPDATE E1 的文本，该字节相等断言必红）；一条 SUPERSEDE(USER_CORRECTION) 事件命名 M2+E2+actor 且带 undo_deadline；重放同一确认 ⇒ 返回同一 M2、无第二个版本；`memory.restore` 撤该更正 ⇒ M1 复 active、head 是指向该 SUPERSEDE 的 RESTORE。单测：`humaux-domain --lib lifecycle`（`CorrectionEvent` = SUPERSEDE+USER_CORRECTION 且拒自更正）、`humaux-application --lib correct`（`authorize_correction` 在 origin 天花板处授权、非继承）、`humaux-adapters --lib memory_governance_repo`（幂等 key = token 摘要 hex）。门：`cargo xtask migrate`（drift 0，无新迁移）/ `rls-check` / `architecture-check` / `cargo test -p humaux-gateway --test mcp_gateway` / clippy / fmt / secret grep。
